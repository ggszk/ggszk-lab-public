    最終課題（Sonic Pi 検証ノート）¶

    1. 課題の目的¶

    前半のレポートで立てた「この要素なら Sonic Pi で表現できそう／難しそう」という予想を， 実際に Sonic Pi で小さく試して検証し，演奏会で答え合わせをする。

    • 曲を完成させる必要はない
    • 自分が選んだ要素について，試したコードが鳴っていて，「予想どおりだった／違った」が自分の言葉で言えれば合格ライン

    2. 作るもの¶

    レポートで選んだ要素を Sonic Pi で試した「検証ノート」（説明＋コード）

    • テーマA（惹かれる音楽）の人：レポートの「これだけは外せない要素」を試す
    • テーマB（仕組み）の人：調べた仕組みを Sonic Pi で試す
    • 小さな実験を 2〜3 個やり，実験ごとに次の 4 つを書く
      1. 予想：何ができそう／難しそうだと思ったか（レポートから引く）
      2. コード：試した Sonic Pi のコード（数行〜十数行でよい）
      3. 鳴らした結果：どう聞こえたか。Sonic Pi のログや画面のスクリーンショットを添えてもよい
      4. 分かったこと：予想と比べてどうだったか
    • 使う文法は参考書 Lesson 3（play・sleep・use_synth・play_pattern_timed・live_loop）の範囲でかまわない。必要に応じて Lesson 7（音階・和音），Lesson 12（リズム），Lesson 10（エフェクト）を使う。困ったら Lesson 3 に戻る
    • 実験の例
      • 「2 ビートと 4 ビートの違いは，アクセントの置き方で出せるか」→ sample と sleep でドラムを 2 通り打って聴き比べる
      • 「暗い雰囲気はコード進行で出せるか」→ chord を :major と :minor で鳴らし比べる
      • 「歪んだキックは作れるか」→ with_fx :distortion の有無で聴き比べる

    曲にしたい人へ

    実験を組み合わせて 1 曲（1〜2 分）にまとめてもよい。その場合も，提出物は「検証ノート」の形（実験ごとの予想・コード・結果・分かったこと）で書き，曲のコードは最後にまとめて貼る。DAW 経験者は，DAW では作りにくいこと（live_loop の途中変化，sync，確率やランダムを使った生成など。参考書 Lesson 14）を一歩上乗せして試してみよう。

    3. 演奏会（第15回・2026-11-10）¶

    • 実験のうち 1 つを実際に Sonic Pi で鳴らしながら発表する（曲にした人は曲を再生する）
    • そのあと 1 分程度の「答え合わせトーク」：レポートで予想したことと，実際にやってみてどうだったかを話す

    5. 締切¶

    2026-11-17（火）23:59（最終回の 1 週間後）。締切の延長はしない。

    • 演奏会（11/10）で発表した内容を，当日のコメントをふまえて整えてから出してよい
    • 演奏会までに，実験のコードを「鳴らせる状態」にしておくこと（第14回で発表準備をする）

    6. 評価の考え方¶

    • 予想が当たっていたかどうかは評価に関係ない
    • 見るのは，自分の要素を試したコードが鳴っているか／予想と結果を自分の言葉で比べられているか
    • 実験の数の多さや，曲としての完成度・長さは問わない

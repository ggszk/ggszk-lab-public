# 教員用：新規テーマ用 GitHub リポジトリ作成チェックリスト

このチェックリストは，**ゼミで研究テーマが確定したとき**に，

教員が GitHub 上で行う作業を整理したものです．

---

## **① リポジトリ作成**

- GitHub 組織（ggszk-lab）で
    
    **ゼミ用テンプレート（seminar-research-template）から作成**
    
- リポジトリ名を決定
    - 年度＋テーマ名（英字・短く・一意）
    - 例：2026-sql-eda-skill
- Public / Private を確認
    - 原則：**Private**
    - 例外：公開前提のテーマのみ Public（ポートフォリオとして）

### **作成先（重要）**

- 新規リポジトリは，**必ず GitHub の個人アカウントではなく，**ゼミの GitHub 組織（ggszk-lab）に作成する
- 個人アカウントに作成した場合は，後から権限・公開範囲の管理が煩雑になるため，原則として避ける．

---

## **② 初期状態の確認（テンプレート確認）**

- 以下のファイル・フォルダが存在することを確認
    - SEMINAR.md
    - 00_context/
    - milestones/
        - 01_proposal/
        - 02_midterm/
        - 03_final/
- 不要なテンプレ説明文があれば最小限に調整（基本は触らない）

---

## **③ 権限設定（重要）**

- **担当学生**を collaborator として追加
    - 権限：**Write**
- **ゼミ学生全員**を閲覧可能に設定
    - GitHub Team を使う
    - Team：seminar-students
    - 権限：**Read**
- 教員は Admin 権限を保持

---

## **④ 初期案内（学生への共有）**

- リポジトリ URL を担当学生に共有
- 以下の作業を学生に依頼
    - SEMINAR.md を読む
    - milestones/01_proposal/README.md を記入
    - 00_context/context.md を記入

---

## **⑤ 最低限の確認（初回レビュー時）**

- 01_proposal/README.md が書かれている
- テーマ・問いが極端に広すぎない
- 明らかに無理な前提が含まれていない
- データ入手や倫理面で問題がなさそうか

---

## **⑥ 例外対応が必要かの確認（必要な場合のみ）**

- 個人情報・企業データを含むか
- 外部共同研究・NDA があるか
- その場合：
    - リポジトリを完全 Private にする
    - 閲覧権限を限定する
